# 🏝️ Zaizai Isle (V1.4.5)

 > 一个可长期维护、可继续生长、可承载个人变化的数字小岛
 > *A digital isle that grows, survives, and reflects personal evolution.*

---

## 1. 产品定位（Product Positioning）

Zaizai Isle 是一个可长期维护、可继续生长、可承载个人变化的数字小岛。

它用来安放创作、想法与生活记录，在持续的积累中留下一些走过的痕迹。

*   **对内（个人留存）**：记录与回看创作轨迹和生活片段，作为理解自己的一方自留地。
*   **对外（温和分享）**：选择愿意公开的内容，让访客在自然的接触中认识岛主；内容随时间自然积累，不设期限，也不背负强运营的任务。
*   **空间意象**：小岛是空间的气质基底，鲸头鹳是陪伴的形象，Vibe Coding 是它自然生长的建设方式。
*   **当前阶段重点**：先承接当下的作品、近期关注与新记录。过去散落在其他平台的内容以后逐步整理，不设迁移期限。文章与生活档案是长期的方向，目前不因定位调整而强行新增庞大模块。

---

## 2. 核心体验目标（Experience Goals）

希望来到 Zaizai Isle 的人，能在一片安静的氛围里，自然地碰见一些真实而有趣的东西。整体的体验可以概括为三个方向：

1.  **静止与流动的平衡**：内容排版保持克制、有边界，但环境（如天气与昼夜的更迭）随着时间静静流淌，呈现出当下的呼吸感。
2.  **自然的个人趣味**：不刻意包装，通过真实的近况、想法与作品，让访客在随意的翻看中，感受到一个真实立体的岛主。
3.  **自在无压的探索**：作品和创作自然呈现，不强加引导；建设的状态与辅助工具则退居其后，保持安静的辅助分量。

---

## 3. 核心信息架构（IA）

采用 **12 列 Bento Grid** 布局，每一个卡片都是一个“低干扰的信息单元”：

*   **Identity Anchor**（身份锚点 / 核心卡片）
*   **Current Forming**（近期真实关注，展示形式待定）
*   **Social Heart**（社交组件 / 联络互动）
*   **Core Build**（构建面板 / 运行、稳定与形成状态）
*   **Built Structures**（被选择保留的岛内外结构）
*   **Living Traces**（天气、日签、留言与访问痕迹）

Tech Stack 与 Node Traces 不再占据主岛首页。Life Passport 由 Built Structures 收纳；已停止服务的外部应用不保留入口。AI Hub 作为“岛主常用工具箱”呈现，Image Compressor 是其中的岛内工具。

**下一轮调整方向（待实现）**：按“遇见岛主 → 碰到作品 → 随意停留 → 了解建设”安排注意力。作品展示优先于通用工具入口，Core Build 保留进度条并后移、缩小，Stats 降为辅助信息。近况是否独占卡片、具体尺寸和最终文案待设计；当前页面尚不代表这一方向已经验收。

## 4. 核心模块说明

### 🪪 Identity Card｜身份卡片
**定位**：呈现岛主长期的身份与气质。
*   拟人化 IP「鲸头鹳」作为气质锚点，校准全站设计的“冷静感”。
*   中/英双重 Slogan 动态重排，适配不同文化语境下的阅读节奏。
*   通过状态切换（Idle, Working, Alert 等）建立轻量互动。

### 🌤️ Weather Card｜环境感知
**定位**：提供“此刻感”的氛围层。
*   实时天气数据驱动渐变背景与玻璃质感图标。
*   昼夜状态联动，确保页面视觉与物理世界的步调一致。
*   异步加载技术确保环境渲染不阻塞主叙事。

### 📊 Stats Card｜行为与数据
**定位**：记录“发生过什么”，而非展示成就。
*   名片下载次数持久化，记录访客的微弱连接。
*   支持一键生成「社交名片海报」，将数字化身转化为可传播资产。

### 💬 Social Card｜低压力社交
**定位**：冷静、有边界的联络方式。
*   WeChat/Email/GitHub 聚合入口。
*   Like 行为带动效反馈，建立无痛点的轻交互。

### 🌱 Current Forming｜当前形成
**定位**：简短呈现岛主近期真实关注，允许尚在寻找开始的方法。
*   使用岛主提供的事实，按实际素材决定结构；不强制生成感悟、问题或鲸头鹳台词。
*   当前确认的关注是艺术史与设计史：想理解今天的审美与设计方式怎样形成，正在考虑如何学习和记录。
*   展示名称、文案和是否独占卡片待设计。现有“先站一会儿”及 AI 文案待替换。
*   随真实关注变化低频更新；记录积累后再评估详细入口，不要求为网站持续生产内容。

### 📂 Built Structures｜已建成结构
**定位**：减少展示，强调构建关系与当前状态。
*   由统一注册表维护结构类型、稳定状态、链接方式与更新时间。
*   岛内结构保持当前页面关系，外部结构明确跳转边界。
*   当前仅展示精选结构；活跃结构超过 6 个前不增加筛选与项目索引页。
*   当前结构为 Life Passport 与 Everything is Banana。
*   下一轮提高展示优先级与空间，让作品比通用工具入口更容易被发现。

### 🧰 AI Hub｜岛主工具箱
**定位**：呈现岛主日常创作、思考与交付中反复使用的工具。
*   仅展示人工精选的常用工具，不以点击时间模拟活跃、退隐或消失状态。
*   Image Compressor 作为岛内工具进入独立页面；外部工具明确使用新标签页打开。
*   下一轮改为更紧凑的辅助区域，不固定 8 列规格。

### 🪪 Life Passport｜人生护照
**定位**：为一次真实的人生抵达盖下印章。
*   使用单页工作台完成记录、装帧、实时预览、私密云端保存与纪念卡下载。
*   提供十二类人生主题、手绘日期选择、可选照片及多种印章与照片质感。
*   照片预览保留原始比例，纸张边缘会随内容尺寸自适应。
*   页面与导出海报共用本地手写字体，章印预览和导出结果保持一致。
*   Supabase 匿名身份、私有数据库与照片存储支持免注册云端护照；恢复密钥可授权新设备访问。
*   本地 IndexedDB 记录可以主动迁移，迁移保留原数据且可安全重试。
*   已保存印章支持详情查看、编辑更新、删除确认与再次导出。
*   Schema v2 提供容量预检、版本迁移与孤立图片/照片标记自动修复。
*   云端保存明确反馈成功或失败；恢复密钥是访问凭证，不提供邮箱找回。
*   **规划中**：增加一个永久岛主账户，通过恢复密钥接入既有护照；访客继续沿用免注册匿名身份与恢复密钥。

### 📖 Isle Daily｜小岛日签
**定位**：在时间里留下一页，不制造连续使用压力。
*   首页呈现当日日签，独立页面支持按日期翻阅。
*   中英文内容、农历/节气与四季主题共同形成时间感。
*   不引入签到、提醒、推荐流与社交指标。

### 📝 Archive｜岛屿沉积
**定位**：时间流逝的痕迹，而非社交动态。
*   弱化实时感，通过留言系统记录“时间的灰尘”。
*   当前是访客留言功能，不等同于岛主文章、图片和日常记录的个人档案库。

### 🏗️ Core Build｜构筑面板
**定位**：岛屿真实建设状态的观测窗口（System Layer）。
*   与 Current Forming 共用一份岛屿状态配置。
*   保留 24 格进度条，但只表达当前版本的四段建设序列，不作为岛屿总体完成率。
*   展示当前形成与稳定化中的真实建设，并记录最近建设脉冲。
*   下一轮移至更靠后、紧凑的位置，保留进度条，不与身份和作品争夺首层注意力。

### 🌱 每日学习｜规划中的私人积累模块
**状态**：产品草案，尚未开发，也不属于当前首页能力。
*   每天提供一则约两分钟的艺术史或设计史内容，减少挑选与开始的负担。
*   保存「有意思」「没感觉」「没看懂」及可选文字反馈，用于回看认识如何变化。
*   每日学习与人生护照共用永久岛主身份；人生护照同时保留访客匿名路径，两类业务数据彼此独立。
*   第一阶段由 Codex 辅助准备少量内容，验证闭环后再讨论定时生成。
*   详细范围见 [每日学习模块 v0.1 产品草案](/zaizai-isle/docs/prd/DailyLearning-v0.1)。

## 5. 技术架构

当前工程底座以静态、可复现和低维护为目标：
*   **动态渲染拓扑**：利用 `next/dynamic` 实现模块级异步加载，首屏 JS 负载最小化。
*   **渲染帧率优化**：采用 `React.memo` 对装饰性高频组件（云朵、动画）进行物理隔离。
*   **12 列栅格系统**：提供更高精细度的布局控制力。
*   **全量 i18n 集成**：所有状态逻辑均已托管，实现语境级适配。
*   **静态发布链路**：Next.js 导出 `out`，推送 `main` 后由 Node 25 GitHub Action 自动发布到 GitHub Pages。
