# 每日一看｜Agent 内容生产与审核流程 v0.1

**状态：开发分支已实现。首次自动草稿生成、页面验收与正式合并待完成。**

## 1. 执行边界

- Agent 自主收集候选作品，生成文章草稿，存入私有数据库。
- Agent 不得自动批准内容。
- 用户核实图片许可与历史来源后，可以批准指定版本。
- 批准后的版本不可直接修改。
- **批准不等于发布**。正式网站内容仍由独立发布流程管理。
- 不覆盖现有 `learning-content.ts`、历史反馈或已发布日期。

## 2. 流程

```text
GitHub Actions（每日 08:00 Asia/Tokyo）
  -> 馆藏 API 元数据
  -> data/learning/research/latest.json
  -> Codex 研究、写作与生成标准草稿包
  -> 岛主在审核页导入草稿包
  -> Supabase 私有表 daily_learning_article_drafts
  -> 岛主审核 /learning/review
  -> 已批准版本（未发布）
  -> 岛主再次确认发布
  -> 不可变公开记录 daily_learning_publications
```

- Agent 使用馆藏缩略图与元数据生成正文。
- 图片不能访问时，Agent 只能根据元数据写草稿，必须保留待核实提示。
- 每条候选作品最多自动生成一份初稿。重复采集不会覆盖草稿。
- 单次采集最多五件候选作品。
- 已批准内容必须保留独立版本。
- 批准与发布是两个独立操作。只有岛主可以把已批准且快照完全匹配的版本写入公开发布表。
- 发布记录不可更新或删除；后续修订必须批准并发布新版本。

## 3. 身份验证

| 路径 | 验证方式 | 数据权限 |
|---|---|---|
| GitHub 定时任务 | GitHub Actions | 只采集公开候选，不生成文章 |
| Codex -> 草稿包 | 项目任务与内容规范 | 研究并生成 `codex_draft` JSON，不批准、不发布 |
| 岛主 -> 草稿导入 | Supabase 用户 JWT + island_owner_accounts | 仅岛主写入私有草稿 |
| 岛主 -> 审核页面 | Supabase 用户身份 + RLS | 仅岛主读取和审核 |
| 岛主 -> 正式发布 | Supabase 用户身份 + RLS + 已批准快照一致性门禁 | 新增不可变公开版本 |
| 公共站点 -> 正式文章 | 现有静态内容 | 不读取私有草稿 |

数据库管理员密钥不得配置在 GitHub 仓库、浏览器或公开文件中。

不再使用 Gemini 或其他站点内模型 API。审核页不会直接调用 Codex；Codex 在项目任务中生成草稿包，岛主导入后进入既有 RLS 审核流程。

## 5. 审核页面

部署后的路径：`/zaizai-isle/learning/review/`。

审核操作：

1. 使用岛主账户登录。
2. 查看最新候选作品或导入一条标准候选 JSON。
3. 导入 Codex 已完成的 `codex_draft` 草稿包。
4. 阅读文章、原图、出处及待核实提示。
5. 核实历史资料和图片许可。
6. 选择「批准当前版本」「退回修改」或「放弃选题」。

**禁止把未经审核的候选数据直接加入公开站点。**
