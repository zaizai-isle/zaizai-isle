# 每日一看｜Agent 内容生产规范 v0.1

> **状态**：模式 A 已确认。规范为首版执行方案。尚未接入定时任务或发布接口。  
> **确定日期**：2026-10-16  
> **依据**：[产品定义](./DailyLearning-ProductDefinition-v0.2.md) · [观察体系 A](./DailyLearning-ObservationFramework-A-v0.1.md) · [历史框架 B](./DailyLearning-HistoryFramework-B-v0.1.md) · [内容编辑规范](./DailyLearning-EditorialGuidelines-v0.1.md)

## 2026-10-30 岛主补充：自动入库与发布分开

- 私有草稿自动接收，无需岛主单独批准入库。岛主只决定指定版本是否正式发布。
- `validateLearningPackageV2.valid=true` 的包即使 `readyForOwnerReview=false`，也应进入私有 `pending_review` / `awaiting_owner_review` 队列。图片许可、可达性、作品匹配或事实证据未解决时，如实保留 `blockers` 和待核状态，供岛主查看、补图与补证。
- 不将未知或受阻字段伪写为核查通过。结构无效时保存研究并报告错误，不编造必填信息。
- 既有受阻包优先补入队列，按内容幂等去重。未批准、未发布且尚无正式审核决定的待审核草稿，补图、补证和正文修订直接更新同一行，保留草稿 ID 与 version；只在已锁定或已发布内容修订时新增版本。历史发布快照不覆盖。
- 审核页直接提供“发布当前版本”；只有发布就绪且岛主点击确认后，才锁定并发布指定版本，无需另做一次人工批准入库。
- 本节优先于下文将 `ready` 作为入队前提的旧流程；事实与图片就绪检查仍用于正式发布。

## 1. 运行模式和权限

**采用模式 A：Agent 自主生产，岛主审核后发布。**

| 操作 | Agent 权限 | 岛主权限 |
| --- | --- | --- |
| 搜索候选作品、拟定选题 | 可自主执行 | 可调整优先级 |
| 核对史实、馆藏与历史关系 | 可自主执行并记录证据 | 可退回或要求补证 |
| 查找图片、核对许可、优化已获准的图片 | 可自主执行 | 可处理例外授权 |
| 生成策划卡、图文草稿、关联阅读 | 可自主执行 | 可修改或退回 |
| 自动规则检查和生成审核报告 | 可自主执行 | 审阅检查结果 |
| 进入待审核队列 | 可自主执行 | 查看候选 |
| **批准发布或批准替换已发布内容** | **无权限** | **必须明确确认** |
| 正式发布、修改已发布版本、对外推送 | **不得自主执行** | 确认后按既定流程执行 |
| 购买许可、公开私人回应、修改账户权限 | **无权限** | 单独决定 |

- 未收到本次内容的明确发布批准时，系统保持 `awaiting_owner_review`。
- 自动检查通过不等于岛主审核通过。
- 岛主不批准时，系统不得通过计时器或默认规则自动发布。
- 本规范不授予 Agent 自动定时运行权限。定时调用和任务预算需要独立配置。

## 2. 数据源规则

### 2.1 作品发现和图片候选

| 等级 | 数据源 | 允许用途 | 必要条件 |
| --- | --- | --- | --- |
| 优先 | [The Met Open Access](https://www.metmuseum.org/policies/frequently-asked-questions-image-and-data-resources) | 作品发现、馆藏资料、图片 | 核对具体作品是否标记 Open Access / CC0 |
| 优先 | [Art Institute of Chicago API](https://api.artic.edu/docs/) | 馆藏筛选、资料、IIIF 图片 | 对应作品 `is_public_domain=true`；遵守接口使用条件 |
| 优先 | [Cleveland Museum of Art Open Access](https://www.clevelandart.org/open-access) | 馆藏资料、CC0 图片 | 确认具体资源提供 CC0 图片 |
| 优先 | [Smithsonian Open Access](https://www.si.edu/openaccess/faq) | 器物、设计史资料、图片 | 确认具体媒体标记 CC0，排除使用限制 |
| 补充 | [Library of Congress](https://www.loc.gov/legal/security-copyright-and-privacy/understanding-copyright/) | 摄影、海报、历史资料 | 逐项核对 Rights and Access；未确认的资源不得发布 |
| 补充 | [Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) | 合规替代图片、摄影 | 核对**具体文件**许可、署名和衍生要求 |
| 研究 | MoMA、V&A、Design Museum、博物馆及专业档案 | 历史背景、馆藏校对 | 页面可访问不构成图片使用许可 |

- 数据源等级决定检索顺序，不替代单件作品的质量判断。
- 馆藏元数据许可与图片许可分开核查。
- Agent 必须保留来源页、馆藏编号、具体图片 URL 和权利说明。
- Agent 不能依据作品年代直接推定具体摄影文件可用。
- 第三方站点、搜索摘要和模型生成文字只能提供候选线索。
- 历史影响、首创性、创作意图等关键论断必须有专业来源或一手史料支持。

### 2.2 使用许可判定

- **可用于发布候选**：具体图片标注 CC0 / Public Domain，或已有明确覆盖本站用途的有效授权。
- **需要补充核查**：标注 No known restrictions、许可不明、来源冲突或含第三方权利。
- **不可自动采用**：存在版权限制、无许可依据、无法确认权利或禁止再利用的图片。
- Agent 不购买授权，不申请付费服务，不通过外链展示规避许可检查。
- Agent 不使用生成图像代替真实历史作品。分析示意如需生成，必须显著标注且不得充当史料。

## 3. 自主选题规则

### 3.1 选题来源顺序

1. 检查[前20期策划矩阵](./DailyLearning-ContentPlan-20-v0.1.md)中的未发布候选。
2. 检查[史料与图片登记](./DailyLearning-SourceAssetRegister-v0.1.md)中的素材状态。
3. 优先选择有具体作品版本、明确观察价值和合法图片候选的选题。
4. 当首批选题缺少合法图片时，将其保留为阻断项。Agent 可以提出替代候选，但不得擅自覆盖原策划项。
5. 在首批策划不足时，从历史节点 B 中选择尚未充分研究的问题。
6. 使用观察主题 A 和方法 M 确定具体切入点。

### 3.2 重复与多样性检查

Agent 每次提出候选时检查最近20期已发布内容和待审核草稿：

- 检查 A01–A08 观察主题和 M01–M06 方法是否集中。
- 检查历史线索 B、地区、时期、媒介、作者是否重复。
- 检查已有作品是否存在可验证的历史关系或观察方法关联。
- 允许少量自由探索内容。不强制覆盖比例。
- 单次选题不因一条主观反馈被排除。
- 优先保证史实和图像合规，不为完成配额降低标准。

### 3.3 两种内容类型

- `single_artwork`：一件作品，一个核心观察问题，一项主要 A、一项主要 M、一项主要 B。
- `related_reading`：以具体历史问题比较多件已核实作品。必须区分史实影响和方法比较。
- **4篇单件观察 + 1篇关联阅读**仅为编辑参考比例。不可作为强制发布节奏。
- 关联阅读必须独立可读。不得要求用户已完成前置内容。

### 3.4 反馈的使用边界

- 第一阶段不自动读取私人反馈，除非岛主在数据访问方案中明确授权。
- 获得授权后，只将明确的兴趣、疑问和理解困难作为弱选题信号。
- 单次「没感觉」不代表排斥整个题材。
- 单次「没看懂」不代表用户能力不足。
- 不建立自动兴趣评分、心理画像或敏感个人推断。
- 私人反馈和自由文字不写入公开文章、外部搜索查询或第三方模型请求，除非另有明确授权和处理方案。

## 4. 生产流程与状态

### 4.1 执行顺序

1. `candidate`：生成候选及选择理由。
2. `researching`：锁定作品版本，核实关键论断与来源。
3. `draft`：生成正文、图文配置及引用清单。
4. `reviewed`：完成自动事实检查、语言检查和内容结构检查。记录机器检查范围。
5. `asset_cleared`：确认全部必要图片的来源、许可及文件可用性。
6. `ready`：自动门禁全部通过，形成固定候选版本。
7. `awaiting_owner_review`：向岛主提供审核材料。此状态不得公开发布。
8. `owner_approved`：岛主对**指定内容 ID 和版本**明确批准。
9. `published`：按现有发布流程执行并记录结果。不得覆盖旧版本。

说明：`reviewed` 和 `asset_cleared` 是独立检查结果。`ready` 不代表人工批准。

### 4.2 异常处理

| 异常 | Agent 处理 |
| --- | --- |
| 来源冲突 | 标记 `blocked_source_conflict`；保留差异与原文证据 |
| 作品版本不明确 | 标记 `blocked_object_version`；停止成稿 |
| 主图许可不明确 | 标记 `blocked_image_rights`；寻找合规替代候选 |
| 图片不可下载或无法访问 | 标记 `blocked_asset_unavailable`；不进入 `ready` |
| 关键论断无证据 | 删除或收窄论断；无法处理则退回 `researching` |
| 重复选题或关联不足 | 说明重复原因，提出其他候选 |
| 生产失败 | 保留日志；不得自动发布旧稿或未经审核的稿件 |

## 5. 每期必须保存的记录

| 记录对象 | 最低字段 |
| --- | --- |
| 选题 | `content_id`、`content_type`、题目、策划序号、A/M/B、候选理由 |
| 作品 | `institution`、`object_id`、作者、标题、年代、媒介、来源 URL |
| 论断 | `claim_id`、论断原文、事实/解释分类、证据 URL、核查结果 |
| 图片 | `asset_id`、具体文件 URL、来源、权利说明、许可依据、署名、尺寸、裁切、可达性 |
| 草稿 | `draft_version`、正文、图片顺序、编辑规范版本、生成时间 |
| 质检 | 每项检查结果、阻断原因、人工待核问题 |
| 审核 | `owner_decision`、批准的 `content_id` 和 `draft_version`、审核时间 |
| 发布 | 已发布内容版本、发布时间、历史版本指针 |

- 审核结果必须绑定具体版本。修改正文或图片后应重新生成审核材料。
- 用户反馈绑定用户当时阅读的已发布内容版本。
- 任何新版本不得覆盖历史阅读快照和私人回应。

## 6. 自动审核规则

Agent 必须检查以下项目。全部通过后才能标记 `ready`。

- [ ] 作品已锁定具体馆藏对象或确切历史版本。
- [ ] 作者、年代、媒介和主要史实可追溯。
- [ ] 创作意图、直接历史影响和首创性等论断具有专项依据。
- [ ] 标题只提出一个主要观察问题。
- [ ] 核心发现与作品的实际可见细节一致。
- [ ] 单篇主要 A/M/B 与正文一致。
- [ ] 历史背景直接服务本期观察问题。
- [ ] 当代连接明确区分历史影响、方法比较和观察迁移。
- [ ] 所有主图、局部图和对照图均通过许可检查。
- [ ] 图片资源能够正常读取，且有署名和替代文本。
- [ ] 正文符合[单篇内容编辑规范](./DailyLearning-EditorialGuidelines-v0.1.md)。
- [ ] 内容不自动公开私人数据或覆盖历史版本。

Agent 无法独立核实的项目应标记待核。**不得将不确定项写成审核通过。**

## 7. 岛主审核包

每份待审核内容必须包含：

1. 内容 ID、版本、类型及建议标题。
2. 完整正文。提供与站点相近的图文预览。
3. 主要 A/M/B、核心发现和选题理由。
4. 全部图片及具体版权、署名信息。
5. 关键历史论断及来源链接。
6. 自动审核结果、阻断项和仍需人工判断的问题。
7. 与已发布内容的重复情况、关联阅读的前置作品。
8. 操作建议：**批准当前版本 / 退回修改 / 暂缓**。

- 只有“批准当前版本”允许进入 `owner_approved`。
- 退回后必须生成新版本；先前批准不自动适用于新版本。
- 如果批准后的资源或正文发生变化，发布前须重新确认。

## 8. 自动运行与技术边界

- 目前只确认业务模式 A。**尚未创建运行任务、数据库迁移或发布接口。**
- 后续如需每天自动生产，必须另行配置运行调度、调用预算、失败重试和任务日志。
- Agent 的数据访问仅采用服务端凭据。不得在仓库、前端或公开环境变量中放置密钥。
- 正式发布操作与内容生产操作必须隔离。生产服务不得拥有直接发布权限。
- 对外部 API 遵守服务条款、速率限制及适用的缓存要求。
- 本地仓库、Supabase RLS、浏览器页面和发布端点的实际权限必须在项目环境中验证。

## 9. 首轮验收标准

**阶段一：人工触发，Agent 自动生产。**

- 至少制作3篇不同类型的候选稿。
- 每篇形成完整审核包。
- 每篇记录实际来源和图片许可。
- 无法通过检查的稿件保留阻断项，不进入待批准列表。
- 岛主可明确批准或退回指定版本。
- 无人工批准时，不产生任何公开发布操作。

**阶段二：按需增加定时生产。**

- 阶段一通过后才配置定时准备草稿。
- 定时任务只生成待审核内容，不自动发布。
- 自动发布属于未来模式 B。需要另行确认。
