# 每日一看｜单篇内容编辑规范 v0.1

> 所属项目：Zaizai Isle · 每日一看  
> 文档类型：单件作品内容的编辑与审核规范  
> 版本：v0.1  
> 修订日期：2026-10-16  
> 适用范围：选题、策划、写作、配图、历史核实、审核和发布。

## 1. 核心规则

**每期围绕一件具体作品、一个观察问题和一个核心发现展开。**

每期同时支持两个目标：

- **目标 A：审美观察力。** 引导用户识别具体视觉特征，并形成个人感受与判断。
- **目标 B：历史理解。** 解释作品相关的历史条件、设计观念及其与当代设计的关系。

编辑应优先保证观察体验。历史背景只需支持本期核心发现。

### 1.1 必须满足

1. 指定一件能够明确识别的作品或设计对象。
2. 提出一个具体、可以从作品进入的观察问题。
3. 提供至少一个可以核对的视觉依据。
4. 说明与核心发现直接相关的历史背景。
5. 提供一个合理的作品关联、当代连接或观察迁移方向。
6. 保留三种固定反馈和可选自由文字。

不得将单篇写成完整艺术运动介绍或知识测验。

## 2. 单篇内容结构

采用**先看 → 发现 → 理解 → 连接 → 回应**的叙事顺序。

| 环节 | 必要内容 | 规则 |
| --- | --- | --- |
| 先看 | 完整作品、基本资料和观察问题 | 先展示作品，再提供必要引入。 |
| 发现 | 1–2 个关键细节或关系 | 描述必须与可见内容对应。 |
| 理解 | 与本期发现直接相关的历史背景 | 不扩展无关生平或运动史。 |
| 连接 | 作品比较、当代连接或观察迁移 | 不制造未经证实的历史影响。 |
| 回应 | 开放问题、固定反馈、可选文字 | 不要求标准答案。 |

五个环节用于编辑。页面不必设置五个固定区块或逐步操作。

### 2.1 标题与引入

标题要求：

- 优先采用具体观察问题。
- 标题能够引导读者查看作品。
- 避免空泛评价和夸张判断。
- 标题应与正文实际解释范围一致。

可用示例：

- 浪这么大，山为什么这么小？
- 这张画，真的是用木板印出来的？
- 为什么我们总是先看向她？
- 地图可以故意画得不准确吗？

不采用的示例：

- 设计之美。
- 包豪斯设计风格全面介绍。
- 彻底改变世界的伟大设计。

引入要求：

- 优先描述用户可以看到的事物。
- 不在首屏提供完整结论。
- 可以提出一个自然问题。避免连续追问。
- 不隐藏必须准确展示的作品信息来制造悬念。

### 2.2 视觉观察

- 从可见元素进入解释。
- 解释应有具体图像或实物依据。
- 一般设置 1–2 个主要观察点。
- 不为填充版面增加没有观察价值的细节。
- 不强制使用“知识点”“学习目标”“本节总结”等课堂标签。

### 2.3 历史背景

优先回答以下问题中与本期有关的部分：

- 作品出现于什么时间、地区及社会背景？
- 创作者面对什么制作或表达问题？
- 作品使用了什么材料、媒介或技术？
- 该作品与当时常见实践有什么具体差异？
- 哪些历史资料支持本期解释？

不得仅凭作品外观断言创作者意图。不得将编辑解释表述为确定史实。

### 2.4 连接

当代连接或作品关联可以采用三种类型。

| 类型 | 固定术语 | 定义 | 必要条件 |
| --- | --- | --- | --- |
| C01 | 历史影响 | 有传播证据支持的技术、形式或观念联系 | 记录具体史料。 |
| C02 | 方法比较 | 比较不同作品的视觉或设计方法 | 明确比较依据；不声称直接影响。 |
| C03 | 观察迁移 | 将一种观察方式用于其他作品或日常设计 | 使用具体对象或情境。 |

不要求每期另配一张当代作品图片。连接内容可以是一句说明。

### 2.5 回应

固定反馈为：**有意思 / 没感觉 / 没看懂**。

- 可以提供一个与本期相关的开放问题。
- 自由文字是可选项。
- 不要求回答开放问题才可提交反馈。
- 不设置知识测验、打卡奖励或学习评分。
- 不根据一次反馈推断用户的稳定偏好。

## 3. 内容策划信息

正式写作前，编辑应填写以下信息。

| 字段 | 必填 | 要求 |
| --- | --- | --- |
| 作品 ID | 是 | 使用稳定标识。 |
| 作品名称、作者、年代、媒介 | 是 | 与可信资料对应。资料存在争议时应说明。 |
| 作品来源 | 是 | 记录馆藏或权威资料页面。 |
| 选题理由 | 是 | 指明本期的观察价值。 |
| 核心观察问题 | 是 | 限定一个问题。 |
| 主要观察主题 A | 是 | 从 A01–A08 选择一个。 |
| 主要观察方法 M | 是 | 从 M01–M06 选择一种。 |
| 次要观察主题 | 否 | 仅记录必要交叉。 |
| 核心发现 | 是 | 用一句话明确预期收获。 |
| 可见依据 | 是 | 指明作品中的具体特征。 |
| 主要历史节点 B | 是 | 关联 H01–H16 或经核准的新增节点。 |
| 必要历史背景 | 是 | 列出需要核实的事实。 |
| 连接类型与内容 | 是 | 选择 C01、C02 或 C03。 |
| 关联作品 | 否 | 记录具体作品及比较关系。 |
| 史料状态、图片状态 | 是 | 与发布状态分开记录。 |

A 和 B 为内部内容策划体系。原则上不在读者页面显示这些分类代码。

参见：

- [审美观察主题 A v0.1](./DailyLearning-ObservationFramework-A-v0.1.md)
- [历史认知框架 B v0.1](./DailyLearning-HistoryFramework-B-v0.1.md)

## 4. 文字规范

- 使用具体、易理解的句子。
- 一句话只承担一个主要事实或动作。
- 优先明确观察对象与动作主体。
- 保留必要的艺术史、设计史与技术术语。
- 新术语首次出现时，使用简短解释。
- 用视觉证据代替无依据的主观评价。
- 不使用夸张、说教或考试口吻。
- 不重复使用固定的引导句式。
- 尊重不同观看感受。不提供唯一审美答案。

### 4.1 长度控制

- 普通单篇以约 2–3 分钟阅读为目标。
- 字数不设硬上限。优先控制信息密度。
- 每期通常只说明 1–2 个视觉观察点。
- 历史背景只覆盖本期需要的事实。
- 复杂历史问题可安排到独立关联阅读。
- 不为控制字数删除必要的史实说明。

## 5. 图文组织

编辑根据作品特点选择图文模式。三种模式可以组合使用。

| 模式 | 适用对象 | 内容顺序 | 必要视觉材料 |
| --- | --- | --- | --- |
| 局部观察型 | 绘画、版画、家具、海报 | 完整作品 → 关键局部 → 整体理解 | 主图；按需局部图 |
| 情境理解型 | 人物摄影、纪实作品、文化艺术 | 完整作品 → 可见事实 → 历史背景 → 重新理解 | 主图；按需同系列照片 |
| 比较发现型 | 信息设计、工业设计、不同版本 | 完整作品 → 观察问题 → 对照 → 设计解释 | 主图；有明确价值的对照图 |

### 5.1 主图

- 每期必须提供一张完整作品主图。
- 保留作品原始比例、颜色及背景。
- 不在作品图像上叠加无关文字、滤镜或装饰。
- 提供足够的清晰度。支持查看高清原图。
- 特殊长幅或高幅作品可调整展示范围，但不得通过强制裁切代替完整观看。

### 5.2 局部与对照图

- 局部图仅用于支持具体观察。
- 局部图统一标注“原作局部”。
- 裁切时保留理解关系所需的上下文。
- 对照图明确标注作品、作者、时间和来源。
- 自制分析示意必须标注为后期示意。
- 不得将重绘、生成或加工图像冒充历史原图。
- 不因模板要求强制使用两张局部图。

### 5.3 媒介适配

| 媒介 | 优先保证的可见信息 |
| --- | --- |
| 绘画和版画 | 完整构图、真实色彩、局部细节 |
| 家具和产品 | 整体外形、材料、结构和操作区域 |
| 摄影 | 人物关系、取景范围和背景语境 |
| 地图和信息设计 | 文字、符号、图例及信息结构可辨认 |
| 建筑 | 整体与局部空间的关系；必要时使用多个真实视角 |

### 5.4 图片来源与许可

每张图片必须记录：

1. 来源页面 URL。
2. 图像资源 URL 或本地资源路径。
3. 作品署名和摄影者署名（如适用）。
4. 权利声明、许可条款及核查日期。
5. 图片尺寸和替代文本。
6. 局部裁切的原图及裁切范围（如适用）。

图片核查包含两个独立方面：

- **权利核查**：是否允许当前网站展示和处理图片。
- **可用性验证**：图片能否在正式网站稳定加载。

馆藏页面可访问，不代表高清图片可自由复制。未经核实的图片不得进入每日主推。来源链接不能代替需要图片的主要阅读体验。

## 6. 事实、解释与伦理边界

| 类型 | 定义 | 审核要求 |
| --- | --- | --- |
| 可见事实 | 可以从作品或原始文件直接核对的信息 | 与图像一致。 |
| 历史事实 | 作者、年代、媒介、事件和历史关系 | 有可靠来源支持。 |
| 编辑解释 | 基于可见事实和背景形成的解释 | 明确依据；避免绝对化。 |
| 个人感受 | 观看者的主观反应 | 不判断正确与否。 |

具体要求：

- 不根据人物表情断言其内心状态。
- 不根据外观推断设计师未经证实的意图。
- 不把形式相似直接写成历史影响。
- 不将历史演变写成简单的优劣替代。
- 不忽略相关的地区、社会和文化背景。
- 不把群体实践归因于单一发明者，除非资料支持。
- 对纪实摄影明确区分画面和被摄者的完整生活。
- 对争议内容注明争议；证据不足时删除相关断言。

## 7. 内容审核与发布

### 7.1 发布前检查表

| 检查项 | 通过标准 |
| --- | --- |
| 作品明确 | 名称、作者、年代、媒介和来源已核实。 |
| 标题有效 | 引导具体观察；不夸张、不空泛。 |
| 观察有效 | 核心发现有可见依据。 |
| 范围明确 | 一篇只聚焦一个核心发现。 |
| 历史可靠 | 关键论断具备可追溯来源。 |
| 解释清楚 | 可见事实、历史事实和编辑解释已区分。 |
| 连接合理 | 历史影响有证据；方法比较不声称继承。 |
| 图片合格 | 主图及必要辅助图权利明确，展示稳定。 |
| 独立阅读 | 未读前期内容也能理解。 |
| 反馈开放 | 保留三种反馈；无标准答案。 |
| 版本可追溯 | 发布内容可定位到具体版本。 |

### 7.2 核心编辑复核

每期审核必须能够回答：

1. 为什么选择这件作品？
2. 读者能从作品中具体发现什么？
3. 这项发现对应什么历史背景或设计问题？
4. 读者可以迁移哪种观察方法，或继续研究什么问题？

无法明确回答时，应收缩选题或修改内容。不得以增加背景段落代替明确观察问题。

### 7.3 工作流程

1. 确定具体作品和版本。
2. 确定核心观察问题。
3. 配置观察体系 A 和历史框架 B 的编辑字段。
4. 核实史料、作品信息和图片使用条件。
5. 撰写正文并选择必要图片。
6. 审核可见事实、历史论断与当代连接。
7. 完成图片可用性与页面检查。
8. 固化正式发布内容版本。
9. 发布并保存用户回应。

## 8. 内容版本与私人记录

- 每期使用稳定内容 ID。
- 正式发布内容保留版本记录。
- 用户反馈绑定当时的内容版本。
- 后续编辑不得覆盖历史阅读上下文。
- 首次反馈应保持可追溯。未来可追加再次回应。
- 私人反馈和笔记默认不公开。
- 未完成权利核查、内容审核或图片可用性验证的选题不得发布。
- 新内容策划不修改既有发布日期或历史记录。

账户权限与性能要求沿用现有专项方案：

- [岛主账户与私人数据方案](./IslandOwnerAccount.md)
- [全站性能契约](./PerformanceContract.md)

## 9. 规范适用边界

本规范适用于**单件作品观察**。跨作品关联阅读可沿用事实、许可、反馈和版本要求，但应单独确定其内容结构。

已完成样稿试写的单篇模式：

- 《十竹斋书画谱》：局部观察型。
- 《移民母亲》：情境理解型。
- 1933年伦敦地铁线路图：比较发现型。

上述模式尚需通过实际阅读和页面验收。不代表全部作品媒介已经完成验证。后续应根据真实样稿更新本规范。
