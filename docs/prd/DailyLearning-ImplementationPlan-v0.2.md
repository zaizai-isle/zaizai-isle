# 每日一看｜规范落地实施计划 v0.2

> 状态：执行中  
> 制定日期：2026-10-20  
> 依据：产品定义、观察体系 A、历史框架 B、单篇编辑规范、内容生产模板、Agent 内容生产规范、性能契约  
> 原则：不覆盖既有发布记录、用户回应或私人笔记；批准与发布保持独立。

## 1. 目标

将当前“可以导入、批准和发布一段正文”的原型，升级为符合 PRD 的内容生产系统。

完成后，每篇内容必须具备：

- 可追溯的内容 ID、内容类型和草稿版本。
- 一项主要观察主题 A、一项主要观察方法 M、一项主要历史节点 B。
- 一个核心问题、一个核心发现和 1–2 项可见依据。
- 逐项历史论断、证据和核查结论。
- 逐项图片资产、许可、署名、尺寸、替代文本和可达性结论。
- 相互独立的事实审核、图片审核和正式环境验证。
- 完整自动质检结果、阻断项和人工待核事项。
- 岛主对指定内容 ID 和版本的明确批准。
- 与批准快照完全一致的不可变发布记录。

## 2. 当前基线与偏差

### 2.1 已具备

- 私有草稿表及岛主 RLS。
- 草稿版本号。
- 批准版本不可修改。
- 批准与发布分离。
- 发布快照不可修改或删除。
- 公开阅读页、反馈和私人笔记。
- Codex 定时生产任务，不自动批准或发布。

### 2.2 必须修正

- 状态只包含 `pending_review / changes_requested / approved / rejected`，不能表达完整生产流程。
- 草稿包缺少策划、论断、图片、质检和规范版本信息。
- 两个人工复选框不足以证明发布条件已满足。
- 候选选择没有强制执行前 20 期、资产登记和重复性检查顺序。
- 审核页没有完整审核包，也没有按阻断项禁止批准。
- 公开阅读页依赖浏览器请求最新内容，关键正文未进入静态初始 HTML。
- 已发布的 `En kommode` 属于原型数据；记录必须保留，但需要新建合规版本，不能覆盖。
- 部分实现说明已经落后于真实代码和数据库状态。

约束：

- `claims` 中未通过的关键论断会形成阻断项。
- 主图必须包含明确宽高、署名、替代文本和许可依据。
- `editorial_caveats` 不能代替结构化阻断项。

## 4. 状态模型

生产状态固定为：

```text
candidate
→ researching
→ draft
→ reviewed
→ asset_cleared
→ ready
→ awaiting_owner_review
→ owner_approved
→ published
```

异常状态作为阻断码记录，不伪装成正常状态：

- `blocked_source_conflict`
- `blocked_object_version`
- `blocked_image_rights`
- `blocked_asset_unavailable`
- `blocked_claim_evidence`

状态门禁：

- 只有 `ready` 可以进入 `awaiting_owner_review`。
- 只有 `awaiting_owner_review` 可以由岛主批准。
- 只有 `owner_approved` 且快照完全一致的版本可以发布。
- 正文、来源、图片或审核结果变化后必须新建版本。
- 退回修改不得直接重写原批准版本。

## 5. 数据库落地

### 5.1 迁移策略

不删除现有表，不改写现有发布记录。采用增量迁移：

1. 为草稿表增加内容标识、类型、生产状态、策划包、论断包、资产包、质检包和规范版本字段。
2. 保留旧 `status`，迁移期增加明确映射；完成页面切换后再决定是否废弃。
3. 新增数据库约束，验证 JSON 类型、大小、固定枚举和关键字段存在。
4. 新增状态转换触发器，拒绝跳过门禁。
5. 发布表增加独立的 v2 快照字段或新建 v2 发布表；旧记录保持可读。
6. 为 `content_id + draft_version`、待审核队列和发布时间建立必要索引。
7. 所有公开表启用 RLS；草稿仅岛主可读写；发布快照仅公开读取、岛主受限插入。

### 5.2 兼容策略

- 现有 v1 草稿显示“旧格式”，不能继续批准为 v2 合规内容。
- 现有发布记录继续保留和读取。
- `En kommode` 后续通过新建 v2 草稿修订，不修改已有发布快照。
- 用户回应继续绑定阅读时的发布条目 ID。

## 6. Codex 生产流程

每次自动任务按以下顺序执行：

1. 读取前 20 期策划矩阵、素材登记、最近 20 篇发布内容和待审核草稿。
2. 优先处理策划矩阵中素材条件可满足的项目。
3. 自由候选必须记录偏离策划矩阵的理由，不覆盖原策划项。
4. 锁定具体馆藏对象和图片文件。
5. 完成多来源研究，并把关键论断拆成 `claims`。
6. 对照原图完成可见事实核查；无法查看原图时停止进入 `reviewed`。
7. 分别完成事实审核和图片审核。
8. 生成完整 v2 审核包和机器可读检查结果。
9. 有阻断项时保存研究结果，但不进入待审核队列。
10. 无阻断项时保存为 `awaiting_owner_review`。

自动任务不得：

- 勾选人工审核项。
- 批准或发布。
- 读取私人反馈作为选题依据，除非岛主另行授权。
- 覆盖旧草稿、发布版本或用户回应。

## 7. 审核页面

审核页按信息层级显示：

1. 作品与主图。
2. 内容 ID、类型、版本和当前生产状态。
3. A/M/B、核心问题、核心发现和选题理由。
4. 接近正式阅读页的正文预览。
5. 关键论断与逐项证据。
6. 图片、许可、署名、尺寸和可达性。
7. 自动检查结果、阻断项和人工待核事项。
8. 重复性与关联阅读提示。
9. 批准、退回修改、暂缓或放弃。

交互规则：

- 存在阻断项时不显示可用的批准按钮，并明确给出修复要求。
- “已核实”不再使用两个无证据复选框；人工结论必须绑定具体审核项。
- 退回修改必须填写意见，并由 Codex 生成新版本。
- 发布按钮只在 `owner_approved` 状态显示。

## 8. 正式阅读页

- 保持完整作品首屏、桌面左图右文、小屏纵向。
- 根据内容模式选择局部观察、情境理解或比较发现布局。
- 没有局部图时使用正文观察布局，不伪造局部图占位。
- 主图保留原始比例、颜色与背景，并可打开原图。
- 图片来源、许可和署名取自已批准资产快照。
- 公开正文优先进入构建产物；浏览器请求仅用于刷新或静态站点兼容回退。
- 历史列表读取不可变发布快照。
- 用户反馈保存发布记录 ID、内容 ID、版本和当时的阅读快照。

## 9. 分阶段实施

### P0｜契约与门禁

- [x] 建立 v2 TypeScript 类型和运行时校验器。
- [x] 为 v2 内容包建立单元测试和无效样例测试。
- [ ] 生成增量数据库迁移。
- [ ] 在本地数据库测试状态转换、RLS 和不可变约束。
- [ ] 部署迁移并运行数据库安全、性能检查。
- [ ] v1 草稿停止进入新的批准流程。

验收：缺少 A/M/B、论断证据、合规主图或存在阻断项的草稿无法批准。

### P1｜生产与审核包

- [ ] 修改自动化提示词，强制读取 PRD 并输出 v2 包。
- [ ] 建立候选优先级、重复性和多样性检查。
- [ ] 建立事实检查、图片检查和质检报告。
- [ ] 重构审核页，完整展示审核包。
- [ ] 生成 `En kommode` 的 v2 修订草稿，保留旧发布记录。

验收：至少 3 篇不同媒介候选形成完整审核包；阻断稿不进入批准队列。

### P2｜发布与阅读

- [ ] 发布动作只接受 `owner_approved` v2 快照。
- [ ] 阅读页按内容模式渲染，并使用已批准资产元数据。
- [ ] 将公开内容纳入静态构建或明确的内容同步流程。
- [ ] 回应记录绑定发布条目和版本。
- [ ] 同步首页卡片和往期内容。

验收：采集、研究、审核、批准、发布和展示完整跑通，且不存在绕过门禁的路径。

### P3｜运营与文档

- [ ] 阶段一达到 3 篇合规审核包后再启用每日自动生产。
- [ ] 增加失败日志、幂等键和重复运行保护。
- [ ] 更新所有实现说明和发布准备文档。
- [ ] 删除或归档已经失效的实现说明。

验收：文档、数据库、自动化提示词和实际页面状态一致。

## 10. 验证矩阵

每一阶段至少执行：

- TypeScript 检查。
- v2 包校验器单元测试。
- 数据库状态、RLS、不可变发布及越权测试。
- 每日一看专项测试。
- ESLint。
- Webpack 生产构建。
- 数据库安全与性能顾问检查。
- 由岛主完成浏览器中的响应式、图片比例、真实内容和完整交互验证。

## 11. 本轮立即执行顺序

1. 冻结当前 v1 导入格式，不再扩展。
2. 建立 v2 类型、校验器和测试夹具。
3. 设计并验证增量数据库迁移。
4. 重构审核页门禁。
5. 更新 Codex 自动化任务。
6. 生成首篇 v2 合规审核包。
