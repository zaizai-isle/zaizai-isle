> 状态：Active（Passport v0.1.11 已实现，等待体验验证）
>
> 创建日期：2026-07-16
>
> 最后更新：2026-08-10
>
> 适用模块：`/achievement`

## 1. 产品方向

将当前“一次性人生成就图片生成器”逐步升级为一个本地优先、长期积累的个人记录工具：

> 用户不是生成一张成就图，而是在自己的人生护照里，为一次真实抵达留下印章。

核心原则：

1. **记录优先**：先完成一段人生记录，再考虑图片美化。
2. **收藏驱动**：每枚印章都进入护照，历史不是附属页面。
3. **分享可选**：分享图是记录完成后的产物，不是使用产品的前提。
4. **本地优先**：第一阶段不要求登录，明确数据保存位置和丢失风险。
5. **允许普通**：不使用排行榜、任务压力和虚构的全球达成率制造价值感。

北极星问题：

> 用户完成第一枚印章后，是否愿意回来留下第二枚？

---

## 2. 核心对象

### 2.1 Passport（人生护照）

第一阶段仅提供一本默认护照：

- 护照名称
- 封面主题
- 创建日期
- 个人宣言
- 护照编号
- 已收集印章数

### 2.2 Stamp（人生印章）

每一次人生抵达的基本记录：

- 唯一 ID
- 成就预设 ID，可为空
- 标题
- 类型
- 日期
- 一句话记录
- 详细回忆，可为空
- 照片，可为空
- 地点，可为空
- 感受或抵达方式，可为空
- 印章样式
- 所属旅程 ID，可为空
- 创建和修改时间

### 2.3 Journey（人生旅程）

由多枚印章组成的叙事合集：

- 名称
- 一句话描述
- 封面
- 印章顺序
- 创建和修改时间

旅程不是待办项目，不强制目标、截止日期或完成进度。

## 3. 总体版本路线

| 阶段 | 版本 | 核心目标 | 用户得到什么 | 进入下一阶段的条件 |
|---|---|---|---|---|
| 0 | Passport v0.1 | 完成概念与架构转向 | 更清晰的盖章流程 | 新流程可完整走通 |
| 1 | Passport v0.2 | 让记录真正留下来 | 第一枚可持久保存的印章 | 保存、恢复、删除稳定 |
| 2 | Passport v0.3 | 形成可回看的护照 | 历史、筛选与年度回顾 | 多条记录仍易浏览 |
| 3 | Passport v0.4 | 让印章组成旅程 | 手动合集、排序与备份 | 数据可安全迁移和恢复 |
| 4 | Passport v1.0 | 成为可长期使用的产品 | 完整、稳定、可访问的个人护照 | 重复记录价值得到验证 |
| 后续 | Passport v1.x | 谨慎扩展同步与分享 | 跨设备或受控分享 | 明确需求后再进入 |

## 4. Passport v0.1：从生成器到盖章流程

### 目标

完成产品叙事、信息结构和代码边界的转向，但暂不引入复杂的数据持久化。

### 用户流程

```text
选择或创建一个抵达时刻
→ 补充日期、文字和可选照片
→ 选择印章样式
→ 确认抵达
→ 预览纪念卡并导出
```

### 功能范围

- 首屏主操作改为“盖下一枚新印章”。
- 支持从现有成就预设选择，也支持自定义标题。
- 照片从必填入口改为可选信息。
- 编辑顺序改为“内容 → 印章 → 照片质感 → 完成”。
- 提供 3 种基础印章样式：
  - 经典圆章
  - 日期方章
  - 手帐异形章
- 现有滤镜收进“照片质感”：
  - 原片
  - 褪色
  - 胶片
  - 复印
  - 实验风格（二级入口，保留现有字符/像素滤镜）
- 导出单枚 1080 × 1440 PNG 纪念卡。

### 工程调整

- 将当前大页面拆分为流程容器、内容表单、样式选择、预览和导出组件。
- 将 Canvas 中的“照片处理”和“卡片/印章绘制”分离。
- 建立稳定的 `StampDraft` 数据结构。
- 将颜色、字体、纸张和印章参数收敛为主题配置。
- 保留当前像素游戏卡作为兼容模板，不作为默认样式。

### 明确不做

- 不做历史记录。
- 不做旅程合集。
- 不做登录、云同步和分享链接。
- 不做多本护照。

### 验收标准

- 无照片也能完成一枚印章。
- 从进入页面到导出最多经过 4 个主要步骤。
- 刷新前能够连续编辑和重新生成。
- 旧有成就预设和主要滤镜仍可使用。
- 手机和桌面端均能完成流程。

## 5. Passport v0.2：第一枚可保存的印章

### 目标

让“确认抵达”产生可持续的数据，而不仅是一张下载图片。

### 功能范围

- 自动创建一本默认人生护照。
- 完成印章后自动收入护照。
- 提供“我的护照”入口。
- 展示印章列表和基础详情。
- 支持编辑、删除和再次导出。
- 首次进入时说明：
  - 数据仅保存在当前浏览器。
  - 清理浏览器数据可能导致记录丢失。
- 支持空状态、保存失败和存储空间不足提示。

### 数据与存储

- 使用 IndexedDB 保存结构化记录与压缩后的本地图片。
- 设置数据结构版本号，为后续迁移预留机制。
- 图片入库前限制尺寸和体积，缩略图与导出图分开生成。
- 不将 Base64 图片长期塞入普通键值存储。

### 明确不做

- 不做旅程编辑。
- 不做跨设备同步。
- 不做公开个人主页。
- 不做未获得印章墙。

### 验收标准

- 刷新页面或关闭浏览器后，记录可以恢复。
- 创建、修改、删除不会产生孤立图片数据。
- 用户能清楚区分“保存到护照”和“导出图片”。
- 删除操作需要确认，并明确影响范围。
- 至少完成一次旧数据结构到新结构的模拟迁移测试。

## 6. Passport v0.3：可回看的人生护照

### 目标

让多枚印章形成时间感，使用户有理由再次打开产品。

### 功能范围

- 护照首页：封面、个人宣言、印章总数、最近抵达。
- 提供三种查看方式：
  - 护照翻页：强调情绪与叙事。
  - 时间线：按日期快速回看。
  - 印章册：按图案和类别收藏浏览。
- 支持按年份、类型和是否有照片筛选。
- 支持搜索标题与记录文字。
- 提供年度自动合集，如“2026 年抵达记录”。
- 提供最近记录与“这一年的今天”。

### 体验原则

- 默认展示已拥有的印章，不陈列大量灰色锁定项。
- 没有照片的记录也必须具有完整、自然的版式。
- 时间线以用户填写的发生日期排序，同时保留创建时间。
- 自动合集可以隐藏，不强制用户接受系统分类。

### 明确不做

- 不做社交动态流。
- 不做完成率排行榜。
- 不做复杂统计仪表盘。
- 不自动分析私密文本。

### 验收标准

- 50 枚印章时仍能快速定位某条记录。
- 三种视图共用同一份数据，不出现计数和排序不一致。
- 筛选条件可清晰恢复默认状态。
- 护照首页在没有记录、1 条记录和多条记录时均成立。

## 7. Passport v0.4：人生旅程与安全备份

### 目标

让独立印章组成用户自己的叙事，同时解决本地数据长期保存的风险。

### 功能范围

- 创建、编辑和删除人生旅程。
- 将已有印章加入或移出旅程。
- 支持一枚印章归入一段主要旅程。
- 支持旅程内手动排序。
- 提供旅程封面和跨页展示。
- 自动建议合集仅作为候选，不自动改动归属。
- 导出完整护照备份。
- 从备份文件预检并恢复。
- 恢复时可选择合并或替换，并预览影响数量。

### 备份要求

- 备份包含清晰的格式版本、导出时间和内容清单。
- 恢复前验证文件结构与资源完整性。
- 合并时通过稳定 ID 避免重复导入。
- 替换属于高风险操作，必须二次确认。
- 对未来版本保留向前迁移入口。

### 明确不做

- 不做多人协作旅程。
- 不做目标打卡和连续签到。
- 不做自动发布。
- 不承诺读取未来未知格式的备份。

### 验收标准

- 用户可以用 3 至 10 枚印章组成一段旅程并重新排序。
- 导出、清空、恢复后，文字、图片、顺序和主题保持一致。
- 损坏或不兼容的备份不会覆盖当前数据。
- 所有破坏性操作都有明确说明和撤销/确认保护。

## 8. Passport v1.0：长期可用版本

### 目标

将已验证的能力打磨成一个稳定、完整、可长期保留的 Built Structure。

### 功能范围

- 完整的新用户引导与隐私说明。
- 统一护照、旅程、印章和纪念卡视觉系统。
- 完善键盘操作、焦点管理、屏幕阅读器标签和减少动态效果模式。
- 优化大批量记录下的列表、图片加载和 Canvas 渲染性能。
- 完整的数据迁移、备份和异常恢复路径。
- 为静态部署环境补齐离线和失败状态。
- 增加匿名、本地优先的产品观察点；若无合适的隐私方案则只进行人工测试。

### v1.0 发布门槛

- 核心流程在手机和桌面端稳定。
- 至少覆盖无照片、长文字、无地点、跨年份等边界情况。
- 100 枚印章的护照仍能流畅浏览。
- 旧版本本地数据升级不丢失。
- 备份可以在全新浏览器环境中恢复。
- 用户能够不阅读说明完成第一枚印章。
- 测试用户中出现真实的第二次记录行为，而不只是一次导出。

## 9. Passport v1.x 候选方向

以下能力只有在 v1.0 验证长期记录价值后才评估：

### v1.1：私密同步

- 可选账号。
- 默认私密的跨设备同步。
- 冲突解决和离线队列。
- 明确的数据下载与账号删除。

### v1.2：受控分享

- 分享单枚印章或一段旅程。
- 默认隐藏地点、详细回忆和原图信息。
- 分享前逐项预览公开字段。
- 可随时失效的分享链接。

### v1.3：年度装订

- 将一年或一段旅程排版成数字册。
- 导出 PDF 或适合打印的版式。
- 所有自动文案均可编辑后再生成。

不建议优先进入的方向：公共广场、点赞排行、连续签到、成就竞争、默认 AI 分析私人日记。

## 10. 跨版本数据策略

数据持久化从 v0.2 才正式启用，但 v0.1 就应先定义统一模型：

```text
Passport
├── Stamp[]
└── Journey[]
    └── stampIds[]
```

每次结构调整必须：

1. 提升 schema 版本。
2. 提供从上一正式版本迁移的方法。
3. 保留迁移前备份或可恢复路径。
4. 以真实图片和长中文文本测试。
5. 不因为渲染主题变化而修改原始记录内容。

渲染结果属于派生数据，可以重新生成；用户文字、日期、照片和归属关系属于源数据，必须优先保护。

## 11. 开发顺序与依赖

```text
数据模型与流程定义
→ 页面组件拆分
→ 多主题印章渲染
→ 本地持久化
→ 护照历史视图
→ 旅程合集
→ 备份与恢复
→ v1.0 稳定性与无障碍
```

关键依赖关系：

- 没有稳定的 `Stamp` 模型，不进入本地持久化。
- 没有可靠的持久化，不开发复杂历史视图。
- 没有历史记录，不开发旅程自动建议。
- 没有备份与迁移，不对外宣称可长期保存。
- 没有重复记录验证，不投入账号和云同步。

## 12. 每个版本的通用完成标准

每一版都必须满足：

- 功能范围与非目标没有发生隐性扩张。
- `npm run lint` 通过。
- `npm run build` 通过；若环境变量缺失，记录未验证原因。
- 手机和桌面关键流程完成手动检查。
- 键盘可完成主要操作，弹窗焦点行为正确。
- 新增数据字段有默认值和迁移策略。
- 新增本地数据有删除方式。
- 图片处理不上传到第三方服务。
- 更新对应版本说明与变更记录。

4. 完成第一枚后，是否自然产生留下下一枚的愿望。

体验结论明确后，再进入 **Passport v0.2：第一枚可保存的印章**。
