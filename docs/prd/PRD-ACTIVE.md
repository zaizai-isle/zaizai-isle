# Zaizai Isle V1.5 执行 PRD

> 版本主题：Living State Calibration
>
> 状态：实施中，尚未发布
>
> 基线日期：2026-10-14
>
> 使用对象：产品、设计、前端与 AI Agent

## 1. 背景

Zaizai Isle 已经形成稳定的岛屿视觉、构建能力与多个实验结构，但首页逐渐更擅长展示功能，而不是回答“岛主此刻站在哪里”。部分活动状态由随机日志模拟，Core Build 也没有准确反映 Life Passport 云端化等真实建设。

进一步梳理后，项目定位明确为个人数字空间：安放创作、想法与生活记录，在积累中认识自己，也让别人认识岛主。V1.5 先校准现有首页，使它能够自然呈现已有作品与近期关注，内容积累能力按实际需要逐步建设。

## 2. 核心目标

> Zaizai Isle 是我的个人数字空间，用来安放创作、想法与生活记录，在持续积累中认识自己，也让别人认识我。

本轮首页体验目标：

让来访的人认识一点真实的我，也碰到几样值得停留的东西。身份、近况与作品优先，建设信息与工具入口承担辅助作用。个人 IP 是长期积累可能形成的结果，不设为本轮增长目标。

本轮先确定文档方向，再设计内容与布局。下述首页层级是下一轮实现依据，尚未全部落实到页面；卡片的具体尺寸与近况呈现形式仍待设计。

## 3. 本轮范围

### 3.1 真实状态

- 用统一配置维护真实近况与 Core Build 建设信息，分别遵循个人关注与工程进展的更新节奏。
- 使用真实的 Life Passport 云端记忆稳定化状态，不再用抽象 Kernel 代表建设进度。
- 移除随机生成时间戳与活动内容的 Live Feed。
- 近况随岛主实际关注变化而更新；建设状态只在真实建设发生时更新，不模拟高频活跃。

### 3.2 首页层级

- 优先让访客遇见岛主：Identity、简短真实近况与联系方式构成入口。
- 保留 12 列 Bento 布局语言；此前首层固定尺寸方案作为现有实现记录，不再作为下一轮验收要求。
- 提高人生护照与 Banana 的可见性和展示空间，让具体作品比通用工具入口更突出。
- Core Build 保留进度条，移到更靠后、紧凑的位置；Stats 降为辅助信息。
- Built Structures 统一收纳 Life Passport 与 Banana；已停止服务的外部结构不再保留入口。
- Weather、Isle Daily 和 Deposits 作为生活与访问痕迹呈现。
- AI Hub 以“岛主常用工具箱”的身份回到首页，人工精选常用工具，不模拟工具活跃度。
- AI Hub 使用紧凑布局，不再要求占据 8 列或大于作品区域。
- Image Compressor 收入 AI Hub，并通过独立工具页使用，不再独占首页卡片。
- Tech Stack 与 Node Traces 退出首页；能力和数据逻辑继续保留。

### 3.3 真实近况的内容依据

- Current Forming 暂作为内部模块名称，不预设必须独占卡片，也不锁定“岛主手记”这一展示名称。
- 近期关注来自岛主本人，允许处于准备、探索或暂停阶段；不强制凑齐标题、说明、问题或感悟。
- 已确认的素材：岛主想系统学习艺术史和设计史，理解今天的审美与设计方式怎样形成，目前正在考虑学习入口与记录方法。
- 这是一项学习意愿，尚不能写成已经开始的课程、已有成果或固定学习习惯。此处记录内容依据，最终首页文案另行设计。
- 现有“先站一会儿”及 AI 相关代写文案未获认可，列为下一轮替换项，不作为人格或内容模板。
- 详细笔记先在顺手的记录方式中积累；有了实际内容后再评估网站入口，不新增学习模块、笔记系统或更新任务。

### 3.4 内容积累的边界

- 先呈现已有作品、近期关注与愿意留下的新记录，允许留白，不要求按栏目生产内容。
- 文章、图片和日常片段是长期可容纳的内容形态，不代表本轮必须建设完整归档、上传或编辑系统。
- 过去其他平台内容以后慢慢整理，不设迁移完成率或期限，也不作为 V1.5 发布条件。
- 需要保存的内容与愿意公开的内容可以不同；本轮不据此承诺私密档案功能。
- 「每日学习」作为后续独立模块记录在产品草案中，当前先完成方向与数据边界评审，不纳入 V1.5 首页校准的开发和验收范围。

### 3.5 文档一致性

- 产品愿景、当前执行 PRD、文档地图与首页结构使用相同定位。
- Life Passport 内部版本独立于站点版本。
- V1.5 验收前不修改正式发布版本号。

## 4. 非目标

- 不新增首页卡片、动态信息流或公开路线图。
- 不自动抓取 Git 提交制造更新日志。
- 不新增后端、CMS、内容运营系统或独立产品。
- 不删除退出首页的工具能力。
- 不以动画或刷新频率证明岛屿活跃。
- 不进行历史内容批量迁移，不新增个人 IP 运营指标或固定发布任务。

## 5. 叙事顺序

首页按以下问题组织，而不是按功能数量组织：

1. **遇见岛主**：身份、简短真实近况与联系方式。
2. **碰到作品**：人生护照、Banana，让人看清并进入体验。
3. **随意停留**：日签、天气、留言与常用工具。
4. **了解建设**：保留进度条的 Core Build 与辅助统计。

这是注意力优先级，不要求额外增加四个可见栏目或说明标题。

## 6. 验收标准

- 首页不存在随机生成的访客、系统自愈或同步日志。
- 近况与岛主提供的素材一致，不虚构学习进度、个人感悟或角色台词；独立卡片不是验收前提。
- 作品的可见性优先于通用工具；Core Build 与 Stats 不再占据首层主导位置。
- Core Build 与统一配置一致；24 格进度条明确表示 V1.5 的四段建设序列，不伪装成岛屿总体完成率。
- Life Passport 只通过 Built Structures 进入，不与结构注册表重复争夺首页位置。
- Smart Exam Platform 与 AI Trainer Assistant 不再出现在 Built Structures。
- Image Compressor 通过 AI Hub 进入独立工具页，不再独占首页卡片。
- AI Hub 保持紧凑、可用；具体列数根据作品优先的布局确定。
- Tech Stack 与 Node Traces 不再出现在首页。
- 中英文状态语义一致，减少动态效果设置仍受尊重。
- `npm run test:passport-storage`、`npm run test:passport-cloud`、`npm run lint` 与 `npm run build -- --webpack` 通过。
- 浏览器视觉、响应式与交互验证由项目负责人手动完成。

## 7. 发布判断

V1.5 完成以本轮验收标准为依据：已有作品和真实近况容易理解与进入，辅助信息分量适当，页面不要求岛主持续填充内容来维持成立。长期价值看创作与记录是否能被保存、回看和继续使用；历史内容迁移、个人 IP 成长和完整归档能力不属于本轮发布条件。
