# 全站性能契约

> 状态：Active · 新增或修改页面、模块时必须遵守
>
> 提炼来源：V1.4.5 首页加载优化（2026-10-13），由首页经验推广到全站
>
> 更新日期：2026-10-14

## 1. 目标

页面开发从一开始就控制初始负担，避免功能完成后再集中拆包、拆样式和补占位。每个页面与模块在实现前，必须先决定它属于关键内容、接近视口时需要的内容，还是用户交互后才需要的能力。

这份契约约束加载时机、代码边界与资源归属，不要求所有内容都延迟加载。每条路由的核心内容应稳定、可读并尽早呈现；非关键功能不能挤占当前页面的初始资源。

## 2. 三层加载顺序

### A. 页面关键内容立即呈现

适用于打开路由时必须看到、影响主体布局或承担主要任务的内容。

- 默认使用 Server Component 或静态 JSX。
- 初始 HTML 必须包含可读主体和完整布局，不能等待 `useEffect` 才出现主要内容。
- 只有确实需要交互的最小部分进入 Client Component。
- 关键组件不得因为方便而导入只在弹窗、导出、上传、预览或设置面板中使用的大型依赖。
- 用户数据尚未返回时，先呈现稳定的页面结构和清晰状态，避免整页空白。

### B. 接近视口时加载

适用于长页面下方的独立区块，以及首页中的天气、留言、日签、工具箱等卡片。

- 独立区块使用动态导入，外层可用 `IntersectionObserver` 在接近视口前预载。
- 当前预载距离以 `500px` 为基线；只有实际体验或测量支持时才调整。
- 等待期间渲染尺寸匹配的占位结构，保留宽度、高度、断点行为和主要轮廓，避免布局跳动。
- 不依赖浏览器 API 的组件保留 SSR；只有访问定位、Canvas、浏览器存储等客户端能力的模块才使用 `ssr: false`。
- 浏览器不支持观察器时应快速回退加载，不能永久停留在占位状态。

### C. 交互或空闲后加载

适用于打开操作后才需要的编辑器、背景控制器、导出器、图像处理、分析脚本及类似能力。

- 设置面板和重型交互在用户点击、聚焦或明确意图出现后加载。
- 分析及非关键第三方脚本在浏览器空闲或首次交互后加载，不阻塞页面主体。
- 必须保留失败回退；基础浏览、阅读和导航不能依赖第三方服务成功返回。

## 3. 组件与数据边界

- 页面与展示组件默认保持为 Server Component；只有状态、事件和浏览器 API 所在的叶子节点添加 `"use client"`。
- 静态外壳与实时行为分开。例如状态栏结构由服务端输出，时间、滚动和可见性监听放在小型运行时组件中。
- 弹窗、海报生成、二维码、图像处理等能力不进入页面初始模块图；在触发时再导入。
- 相互独立的数据请求并行开始，不能无理由串行等待；只在真正需要数据的分支中 `await`。
- 同一页面的全局监听器集中管理并在卸载时清理；滚动监听使用被动模式，不可见时暂停计时器、轮询和重型动画。
- 不为简单文本、静态图标或单一展示状态创建新的 Client Provider。

## 4. 样式、翻译与资源

- 全局样式只保留跨路由共同基础；Life Passport、Banana、每日学习等页面的样式从各自入口加载。
- 列表和入口使用合适尺寸的缩略图，高清资源在预览、导出或详情页中加载。
- 静态图片声明合理的响应式尺寸；只有当前页面真正关键的视觉资源可以提高加载优先级。
- 翻译、配置和数据按路由及使用边界拆分，避免一个页面为未显示的模块或语言加载整包内容。
- 新依赖加入任何页面前，先检查它是否可以放到交互分支、独立路由或原生浏览器能力中。
- 独立模块不得把大段专属 CSS、字体或素材重新带回全局入口。

## 5. 占位与布局稳定性

延迟内容的占位是布局契约：

- 占位尺寸、移动端最小高度和断点行为必须与真实内容一致。
- Bento 卡片还必须同步 `colSpan`、`rowSpan` 和圆角；卡片尺寸调整时，同一改动必须更新占位参数。
- 占位不模拟虚假内容，不使用持续吸引注意的动画。
- 占位带有可审计的数据标记；辅助技术只获知简短加载状态。
- 数据加载完成后避免替换整个页面骨架，只更新对应内容区与状态。

## 6. 新页面与模块的开发顺序

1. 先说明页面的主要任务，以及用户打开后必须立即看到什么。
2. 在写交互前确定三层加载归属、服务端/客户端边界、数据请求关系和占位尺寸。
3. 把重型能力放入动态导入边界，再实现业务逻辑。
4. 检查新增导入是否把其他路由的样式、第三方 SDK、Canvas、编辑器、高清素材或完整数据集带入初始路径。
5. 运行 lint 与生产构建；涉及视觉布局时由项目负责人手动检查占位、真实内容与路由切换是否跳动。

## 7. 评审问题

每次页面变更至少回答：

- 用户打开这条路由时，哪些内容必须随第一批资源加载？
- 主体能否作为静态或服务端内容出现，只把交互叶子交给客户端？
- 页面下方或次要区域是否在接近视口前才请求代码和数据？
- 点击后才使用的依赖是否已经移出初始模块图？
- 占位是否保留真实内容的几何尺寸和响应式行为？
- 样式、翻译、字体、图片和 SDK 是否只加载当前入口需要的部分？
- 相互独立的数据请求是否并行，失败是否被限制在对应区域？
- 失败、无 JavaScript 或不支持观察器时，主体内容和导航是否仍可使用？

## 8. 首页专门规则

- Identity、主要作品入口等首屏内容保持静态或服务端优先。
- 首屏下方卡片沿用视口预载与 Bento 占位方案。
- 首页不加载独立作品页的编辑器、海报生成、图像处理和专属样式。
- 背景控制、分析脚本和类似非关键能力沿用交互或空闲加载。

## 9. 验证边界

代码验证包括：

- `npm run lint`
- `npm run build -- --webpack`
- 静态导出包含所有受影响路由和文档页面。
- 检查新增组件的导入边界、`"use client"` 范围、数据瀑布和动态加载回退。

浏览器中的关键内容出现速度、布局跳动、网络瀑布、响应式与交互验证由项目负责人手动完成。发现退化时，先修正加载边界，再扩大功能。
