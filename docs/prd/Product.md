## 1. 产品定位与哲学 (Core Philosophy)

> Zaizai Isle 是我的个人数字空间，用来安放创作、想法与生活记录，在持续积累中认识自己，也让别人认识我。

项目首先服务于创作与认识的积累：留下作品、文章、图像和日常片段，让它们可以被保存、回看和联系起来，帮助岛主理解“我何以是我”。个人 IP 可以随着这些积累逐渐形成，不作为每次更新的任务或流量指标。

“小岛”是空间的气质，鲸头鹳是它的辨识形象。Vibe Coding 是建设方式；这些表达与技术共同服务于内容的长期安放。

首页的中心句是：

> 让来访的人认识一点真实的我，也碰到几样值得停留的东西。

身份、真实近况和被选择保留的作品共同表达岛主的趣味。人生护照、Banana、日签等具体体验值得获得注意力；建设信息与常用工具为这些体验提供辅助。

取舍时先判断一项内容能否帮助自己保存与回看，或帮助访客认识岛主、体验作品和自在停留，再决定呈现方式。首页是选择后的窗口，不必容纳全部记录。

### 积累的节奏

- 先承接当下的创作、关注和愿意留下的新记录，栏目不必填满，也不设固定更新频率。
- 过去其他平台的文章、图片和零散日常以后逐步整理；迁移不是当前版本的前置条件。
- 后续整理旧内容时保留原始时间、出处与背景，今天的回看另行注明；公开范围由岛主选择。
- 允许兴趣变化、想法修正和记录不完整，不要求每份内容形成结论或统一人设。
- 当前尚未具备完整的文章、图像与日常归档能力；具体内容功能随实际素材和使用需求设计。

### 当前值得验证的积累方式

岛主希望系统理解艺术史与设计史，但挑选内容和开始学习本身会消耗精力。项目计划先验证一个私人「每日学习」闭环：每天递上一则足够小的内容，由岛主留下「有意思」「没感觉」「没看懂」或一句自由反馈，并保存当时的内容与反应。

这项尝试的目的，是降低开始的门槛并形成可回看的认识记录。它不要求打卡，也不立即承担公开内容或个人 IP 运营。具体范围以 [每日学习模块 v0.1 产品草案](/zaizai-isle/docs/prd/DailyLearning-v0.1) 为准。

### 核心特质：
*   **非效率导向**：保留“无用”但有存在感的设计（如昼夜节律、鲸头鹳的静止）。
*   **环境叙事**：信息不只是文本，而是空气、光影和时间的沉积。
*   **低心智负担**：单人可维护，AI 可随时介入协作，系统逻辑纯净。

## 2. 三层叙事协议 (Narrative Layer Contract)

以下三层用于协调内容、氛围与技术的关系，不要求每份记录归类，也不作为新增栏目或限制个人表达的规则。

### 第一层｜运行层 (System Layer)
*   **定位**：岛屿地下的地质结构与生态规则。
*   **对象**：结构稳定性、AI 可理解性、长期可扩展性。
*   **语言**：冷静、明确、无情绪（如：*Kernel, Boundary, Active, Stable*）。

### 第二层｜世界层 (Island / Metaphor Layer)
*   **定位**：访客路过时看到的岛屿风貌。
*   **对象**：访客情绪、体感认知、隐喻系统。
*   **语言**：适量使用具象隐喻，保持入口易懂，让氛围支持内容阅读。

### 第三层｜意义层 (Personal / Poetic Layer)
*   **定位**：安放岛主真实的创作、想法与生活记录。
*   **对象**：个人经验、关注、认识及其变化。
*   **语言**：依内容自然表达，可以具体、日常或尚无结论；不强制诗性，也不限制个人内容的数量。

## 4. 关键原则与边界 (Guardrails)

### 4.1 鲸头鹳 (Shoebill Agent) 准则
*   它是岛屿的代理人格，不是系统的本体。
*   它应该是冷静、站得很久、一击必中的。
*   这种气质体现在表达节奏、留白与交互分寸中；文案使用岛主真实的经历和关注，不为鲸头鹳编造哲理或角色台词。
*   **设计校验**：“这个改动，会不会打扰到正在路过的人？”

### 4.2 扩建边界 (V2.0 Boundary)
在进入 V2.0 之前，必须满足：
1.  **单人维护**：无须投入专门精力进行内容运营。
2.  **低噪增长**：不追求热闹，追求准确。
3.  **积累优先**：把时间留给创作、学习与生活，建设随实际内容需求推进。
